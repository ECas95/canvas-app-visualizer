# Canvas Source Format Support

Canvas App Visualizer distinguishes current Canvas source from historical source. It does not pretend that every YAML dialect is equivalent.

## Current source: `.pa.yaml`

The primary format is the active Power Apps Canvas source-code format generated by current Power Apps tooling.

Supported top-level concepts:

- `App`
- `Screens`
- `ComponentDefinitions`
- `DataSources`
- `EditorState`

Supported control creation metadata includes:

- `Control`
- control version suffixes such as `@1.2.3`
- `Variant`
- `Layout`
- `Group`
- `MetadataKey`
- `IsLocked`
- `ComponentName`
- `ComponentLibraryUniqueName`
- ordered `Children`

The project includes the official public Microsoft Canvas v3 schema and validates current source locally with Ajv.

See `THIRD_PARTY_NOTICES.md`.

## Current `.msapp`

A current `.msapp` can be opened when it contains `.pa.yaml` under `Src/`.

The importer:

1. opens the ZIP-compatible package locally;
2. applies file-count and expanded-text safety limits;
3. selects current `Src/*.pa.yaml`;
4. ignores package JSON as unstable source material;
5. parses and validates the selected Canvas source.

When current and legacy source are both present, current `.pa.yaml` wins.

## Retired experimental source: `.fx.yaml`

The retired experimental `.fx.yaml` format is supported **read-only** for historical/community packages.

The compatibility parser understands common patterns found in public PnP Power Fx samples:

- `Screen1 As screen`;
- `App As appinfo`;
- `Component As CanvasComponent`;
- nested `ControlName As control.type` declarations;
- groups represented as nested controls;
- direct serialized properties;
- explicit legacy `ZIndex`;
- quoted names/types;
- component function declarations whose parameters contain `As`.

Legacy source is never presented as the active authoring format.

See [Public .msapp Research Corpus](MSAPP_RESEARCH_CORPUS.md).

## Generic YAML

Plain `.yaml` / `.yml` files can be opened.

The visualizer attempts structural inference:

- modern top-level Canvas nodes → current mode;
- legacy `Name As Type` declarations → legacy mode;
- otherwise → unknown Canvas YAML.

Unknown YAML can still be inspected for parse problems, but no compatibility claim is made.

## Power Fx

All serialized formula values beginning with `=` are indexed.

The fast TypeScript layer now understands enough lexical structure to distinguish:

- strings;
- quoted identifiers;
- comments;
- identifiers;
- numbers;
- operators;
- records/tables/delimiters;
- function-call expressions;
- qualified component function calls.

This prevents common regex false positives.

It is not a replacement for the official Power Fx parser/binder. The semantic plan is documented in [Power Fx Compatibility Architecture](POWER_FX_COMPATIBILITY.md).

## Important limitation

Microsoft documents the Canvas YAML schema as actively developed and potentially incomplete.

Compatibility is therefore tested and versioned rather than assumed.

The visualizer is an inspection/analyzer tool. It does not claim that source accepted by its static checks will necessarily load or behave identically in Power Apps Studio.
